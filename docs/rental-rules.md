## 1. 租借類型（bookingType）

| 類型 | 代碼 | 說明 |
|---|---|---|
| 小量 | `little` | 個人少量借用，有數量與押金上限 |
| 大量-個人 | `mass-personal` | 大量借用（個人） |
| 大量-團體 | `mass-group` | 大量借用（團體） |

設備與空間**各自獨立**選類型與日期。（`DateSelectionContext.tsx`）

三種代碼是**全站語義**，但兩個頁面的 UI 標籤對應不同（`DatePickerBar.tsx` `handleBookingTypeChange`）：

| 頁面 | UI 選項 | 實際 bookingType |
|---|---|---|
| 設備頁 | Light 小量 | `little` |
| 設備頁 | Mass 大量 | `mass-personal` |
| 空間頁 | Personal 個人 | `little` |
| 空間頁 | Group 團體 | `mass-group` |

> 歷史教訓：空間頁 Group 曾誤設 `mass-personal`，導致所有「`mass-group` 才放行」的邏輯（押金豁免、全選）從未生效。改對應前先全域搜尋三種代碼的判斷點。

## 2. 日期選擇

- **設備日期**與**空間日期**分開管理；每種各自保留「小量」與「大量」兩組日期，切換類型時不互相覆蓋。（`DateSelectionContext.tsx`）
- **最小可選日期**（`DatePickerBar.tsx` `getMinSelectableDate`）：
  - 小量 → **今天**
  - 大量（設備）→ **今天 + 3 天**
  - 大量（空間）→ **今天**（不延後）
- **最長租借天數**（`DatePickerBar.tsx` `maxDays` → `Calendar.tsx`）：
  - 設備 → **30 天**
  - 空間（教室 + 編號區）→ **14 天**；大四／碩士 → **30 天**（✅ 已實作，
    `gradeUtils.isSeniorOrGraduate`，`DatePickerBar` 與 `DateEditDialog` 的 `maxDays`）
- **選擇有效期 24 小時**：超過 24 小時未送單，日期選擇自動清除。（`EXPIRY_TIME`，每分鐘檢查一次）
- **起租日過期自動調整**：
  - 小量：起租日若已過去 → 自動改成今天，保留原本天數。
  - 大量：起租日永遠應等於「今天+3（設備）／今天（空間）」，不符就重算。
- 選好歸還日後日曆自動收合。
- **日曆不可翻回過去**：最早只能停在本月（`Calendar.tsx` `canGoPrev`）。
- **編輯日期對話框**（`DateEditDialog.tsx`）同樣依類別限天數：空間 14／設備 30。
- **Exist Cart 過期時段就地修復**：購物車內過期時段仍顯示於「已選日期」清單，帶黃色 Expired 標籤，點擊直接開 `DateEditDialog` 重選並帶入新日期（不隱藏、不禁用——這是全站 UX 原則：過期項目保留可見＋標籤＋就地修復）。（`DatePickerBar.tsx`）

## 3. 數量上限

- **小量設備**：同一時段最多 **9 件**，以實際數量計。（`useCart.ts` `checkLittleBookingLimit`）
  - 空間（個人）**不佔額度**，由押金 cap 5,000 天然限量（2026-09-30 定案、2026-10-02 隨分單實作）。
- **大量訂單**：無數量上限，但**每張單須滿 10 件**才能送單（分單後大量設備、團體空間各自計）（結帳時驗證，checklist 顯示「大量租借需滿 10 件」）。（`useCartValidation.ts`）
- UI：小量達 9 件時，日期選單該時段顯示「(已達上限)」並禁用。（`DatePickerBar.tsx`）

## 4. 押金

### 上限
- **每時段、每類別上限 NT$5,000**（`DEPOSIT_CAP_PER_CATEGORY`）：
  - 設備類：上限 5,000
  - 空間類（教室 + 區塊）：上限 5,000
- 「加入時即時擋」與「結算時 cap」的分工（`useCart.ts` `checkDepositLimit`）：

| bookingType | 設備押金 | 空間押金 |
|---|---|---|
| `little` | 即時擋 5,000 | 即時擋 5,000 |
| `mass-personal` | **不擋**（數量不限，結算 cap） | 即時擋 5,000 |
| `mass-group` | **不擋**（結算 cap） | **不擋**（結算 cap） |

- 空間頁對個人租借（非 `mass-group`）再往前擋一層：**點選格子當下**就檢查（已選＋該時段購物車內空間押金＋這一格 > 5,000 → 擋），且**全選（Select All）僅開放大量-團體**（個人全選必超標，格子位置應由使用者自選）。（`SpacePage.tsx`）
- **送單結算**：設備與空間押金各自 `Math.min(…, 5000)`；顯示端（`CartList`、`OrderPage`、`RentalListPage`、`SpacePage.calculateTotalDeposit`）同樣以 cap 後金額呈現。（`useOrderSubmission.ts`）

### 單價
| 項目 | 押金 |
|---|---|
| 教室 A503 / A507 / A508 | 每間 **NT$5,000** |
| 區塊・後陽台（L1–L6） | 每塊 **NT$2,000** |
| 區塊・其他區域 | 每塊 **NT$1,000** |
| 設備 | 各設備資料自帶（`equipment-data.json`） |

## 5. 類型共存（同一時段購物車內）

（`useCart.ts` `checkBookingTypeConflict`；2026-10-02 隨分單改寫）

**購物車內（不分時段）設備只能小量／大量擇一、空間只能個人／團體擇一**（2026-10-02 Bernard 定）：
- 設備與空間可同時存在購物車，送單時自動拆成兩張訂單（一張訂單＝同類別 × 同時段，`cartGroupKey`）。
- 例：小量設備＋團體空間 ✅；小量設備＋大量設備 ❌（不論是否同時段）；個人空間＋團體空間 ❌。
- **切換類型當下就提示**（2026-10-02，`DatePickerBar.handleBookingTypeChange`）：日期列點了與購物車同類別訂單
  衝突的類型（例：已有小量設備卻點「大量」）→ 不切換，跳提示——該訂單**已過期**：提示需要 Renew，按鈕直接開
  日期編輯；**仍有效**：提示「已達訂單上限」，按鈕前往購物車送出或清除。加入時的 `checkBookingTypeConflict` 仍為防線。

## 6. 重複下單（對照已送出訂單）

（✅ 2026-07 已搬 server 端——`submit_orders` 內同規則檢查；原前端 `orderValidation.ts` 讀 localStorage 的
提前提示已於 2026-10-03 刪除，由 `DatePickerBar` 的同類型未歸還檢查〔§7 新規則〕取代）

- **時間完全相同 + 同類別（設備／空間）+ 兩者都是小量** → ❌ 不允許（一個時段每類只能一張小量訂單；
  分單後小量設備與個人空間互不影響）。
- 其他完全重疊組合（小量↔大量、大量↔大量）→ ✅ 允許。
- 時間部分重疊 / 完全錯開 → ✅ 全部允許。
- **已有同類型設備單要加設備 → 改原單**（2026-10-03，order-lifecycle 情境 3）：小量／大量設備單送出後，
  取件前可增減、取件後只能加（新增待學會點交）；小量 ≤ 9、大量 ≥ 10。日期列被同類型擋下時直接帶去修改。

## 7. 設備庫存

- 可借數量 = 庫存 − 該時段生效訂單（待繳押金／租借中／逾期）佔用 − 購物車內同設備數量。
  （`EquipmentGrid.tsx` `getAvailableQuantity`；佔用由 `equipment_reserved` RPC 即時算，送單時 `submit_orders` 鎖列再查一次）
- 加入超過可借數量會被擋，顯示「庫存不足」。
- **On hold**（型錄「待繳押金」欄）＝佔用中押金還沒繳的部分：待繳押金的單＋小量取件後新增、尚未點交補押金的品項。
  押金已繳的直接扣——已繳待取件、大量單取件後新增（2026-10-03 Bernard 定）。

## 8. 送單與訂單編號

- 購物車依「設備／空間 × 時段」分組（`cartGroupKey`），**每組產生一張訂單**。
- 訂單編號格式：`#{年份}{三位流水號}`，例：`#2026001`。（`useOrderSubmission.ts`）
- 送出後：清空購物車與日期選擇、導向 `/profile`，並發預約成功通知（`submit_orders` 同一 transaction 寫入）。

## 10. 押金繳交 / 歸還 / 罰款

- 📝 文案：送出後「請於 **24 小時內**至系學會繳交押金」；押金限現金，**繳交後預約才成立**。
- 逾期相關（2026-07 已實作，詳見 order-lifecycle.md 情境 1／6／7）：
  - 歸還時限：**有效歸還期限**（歸還日撞週末／公休日／法定假日順延到下個營業日）19:00 前完成
    ——不營業日＝週六日＋`closed_dates`（學會公休：學會辦活動／大總評／其他；法定假日：後台自動匯入），
    兩者效果相同；寒暑假則是 `rental_blackouts` 擋新單（見 order-lifecycle 情境 11-a）
    「清潔歸還」，19:01 起算逾期——pg_cron 自動標記 `overdue`（`auto-overdue.sql`）。
  - 逾期罰款：第 1 日 100 元、之後每日翻倍**累計**（週末節假日不計），上限為押金總額；
    逾期中前端即時試算（`timeUtils.overduePenalty`），歸還時最終金額寫 `orders.penalty_total`。
  - 停權：單筆逾期達 **6 個營業日**＝未完成「清潔歸還」→ 自動 `account_level = 5`、
    擋送單不擋登入（`account-suspension.sql`＋`submit_orders`），人工解鎖。
  - 帳號狀態 **6 級**：app 顯示用設計（官方文件無分級制）——第 1 級無逾期、
    第 2–6 級＝當前最嚴重單逾期 1–5 個營業日，即時計算不入庫（`ProfilePage.tsx`）。
- 📝 文案（規則已定、程式未實作）：未經預約使用罰 200 元／次；歸還審核狀態機屬階段 2 後台。

## 11. 延期（Extend）

（`ProfilePage.tsx`、`ExtendDialog.tsx`）

- **只有「租借中（in-progress）」且未延期過的訂單可以延期**。
  - 過期／取消（canceled）的訂單**已失效，不可延期**——延期也救不回來。
  - 逾期（overdue）、已歸還（returned）、待繳押金（pending）同樣不可。
- **僅可延期乙次**：`hasExtended` 標記，延期過的訂單按鈕直接禁用。
- **最多延期 7 天**，天數從原歸還日往後計算（dialog 只提供 1–7 天選項）。
- **需在原歸還日前三天（含）提出**（2026-07-14 定案為**程式強制**）：申請當日須 ≤ 歸還日 − 3 天，
  過期即不可延期、訂單照常結束；仍想借須重新下單走先來後到。於 `extend_my_order` RPC 依日期擋，
  `ExtendDialog` 同步禁用按鈕。（官方原文規則，非新增。）
- 📝 文案：「訂單內所有空間/設備需可同時延期」——⚠️ mock，目前無真實佔用資料可檢查。

## 年級限制（✅ 2026-07 已實作）

> `'1'`–`'4'` 或「大一」–「大四」，碩士含「碩」字樣；**未填或格式不符一律從嚴視為一般生**

- **大四／碩士生：空間最長 30 天**：`gradeUtils.isSeniorOrGraduate` →
  `DatePickerBar.tsx` 與 `DateEditDialog.tsx` 的 `maxDays`（教室＋編號區整個空間頁）。
- **A508 教室：限大二以上**（含碩士；大一擋）：前端 `SpacePage.handleClassroomAdd`
  toast 提前提示，`submit_orders` server 端為真正防線（`v_sophomore_up`）。

## 帳號身分（✅ 2026-10-01 已實作，後台「會員管理」`AdminMembersPage` 維護）

- **休學**（`students.on_leave`）：**擋新借，同停權**——`submit_orders` 拒絕送單；已借的照常歸還／延期。
  復學在後台取消勾選即恢復。前端無提前提示，送單時顯示 server 錯誤訊息。
- **系秘＝助教**：同一個 `role = 'staff'`（免押金、送出即租借中，見情境 10），不另設身分。
  **系秘不當經手人**——收押金／歸還的經手人只有系學會（2026-10-02 Bernard 確認）。
- **轉學生**（`students.is_transfer`）：純標記，不影響任何規則；年級照實際填。
- **系學會**：`staff_members` 表＝收押金／歸還的經手人名單，在會員管理把身分設為「系學會」即加入（原幹部名單頁已併入）；**違規**（停權／逾期中／欠罰款）由現有資料即時算，不入庫。
- 後台顯示身分四選一（優先序）：管理員＞系秘＞系學會＞學生；轉學生／休學另以標記呈現。
- **班級**：後台以「日媒四乙」「碩媒一甲」顯示與編輯，實際存 `grade`（大四／碩一，規則判斷用）＋
  `class_name`（甲／乙），`gradeUtils.classLabel`／`parseClassLabel` 轉換；9/1 升級只動 grade，標籤自動跟著變。
  **不從學號代碼推班別**（2026-10-02 Bernard 定）：正式名單會連年級／班級自動匯入後台；前台 Profile 同樣顯示名單資料。
- **畢業生帳號（方向定案 2026-10-02，待實作）**：原則上**自動停用**，**有東西沒歸還者除外**（歸還結案後再停用）。
  待定細節：判定時點（例如 9/1 升級時仍為大四／碩二者？延畢由後台調年級）、「停用」＝不能登入還是只是不能借。

## 2026-09-29 新規則（已拍板，待實作）

> 團隊討論定案；對應實作任務已列入 roadmap.md 階段 2／3。

1. **A508 與後陽台預設不開放租借**——後台加 toggle，系學會可隨時開放／關閉。
   開放期間 A508 仍維持「限大二以上」（見年級限制一節）。後陽台＝區塊 L1–L6。
2. **押金上限明文化：一個時段總上限 NT$10,000＝空間 5,000 ＋ 設備 5,000 分開計**——
   現制已如此（第 4 節 `DEPOSIT_CAP_PER_CATEGORY` 兩類各 cap 5,000），此條僅正式定調，程式不需改。
3. ✅ **大量租借設備可先繳押金、後取件**（2026-10-02 定案並實作，SQL 見 `supabase/mass-pickup.sql`）——
   學生在購物車填借用資訊時選兩個時段，選項＝**系學會值班時段**（日期＋值班時段）：
   - **取件時段**：固定在**起租日當天**。
   - **繳押金時段**：送單後 **24 工作時內**、且不晚於取件時段（選同一時段＝繳押金與取件同時進行）；
     逾時未繳的自動取消規則不變（情境 1）。
   - 時段選項來源＝會員管理的系學會值班時段；**值班表在開放租借前一定排好**（2026-10-02 Bernard 確認），
     不用擔心起租日沒有值班時段。
   - 後台收押金時可勾「同時取件」→ 租借中；不勾＝只收押金 → **已繳押金・待取件**（status 仍 pending，
     `deposit_paid_at` 有值，不會被自動取消），之後按「取件」→ 租借中。
   - **已繳押金但逾時未取件**：後台訂單頁與總覽紅字提醒「逾時未取件」，由學會手動處理（聯絡或代取消＋退押金），
     不自動轉狀態。
4. ✅ **設備與空間分單**（2026-10-02 實作）——同一時段的設備與空間拆成兩張獨立訂單，不再共存同一張單。
   購物車組別＝訂單（`cartGroupKey`）：借用資訊各填、9 件／押金／類型互斥各自算、送單各自成單；
   `submit_orders` 擋混合單。後台種類欄四格：小量設備／大量設備／個人空間／團體空間。
5. ✅ **Order 頁提示加「現金交易不找零」**——放在「押金限現金」既有文案旁（2026-10-03，畫面＋PDF 收據）。
6. **後台空間 map 視圖**——沿用前台 `SpaceAreaMap` 顯示各區塊當前租借狀態，
   最好能看到被誰借走（點區塊顯示借用人／訂單）。
7. ✅ **購物車一次只能各一組訂單（2026-09-30 定案、2026-10-02 實作）**——小量設備／大量設備／個人空間／團體空間
   **各最多一組（一個時段）**，不能同類型分多個時段一起下單。
   依據：學會規定**上一個訂單歸還後才能開啟下一個訂單**。
   **兩層強制**：
   - 購物車層（UX）：`useCart.checkBookingTypeConflict` 加入時擋——同類別（設備／空間）已有訂單時，
     類型不同或時段不同都擋（既有訂單過期則提示先重選日期）；規則上線前的舊購物車由
     `useCartValidation.singleOrderValidation` 在結帳擋。日期列點衝突類型時當下提示（§5）。
   - **server 層（真正防線）**：`submit_orders` 擋「已有同類型**未歸還**訂單」——
     同類型＝上述四格之一，未歸還＝`pending`／`in-progress`／`overdue`
     （`returned`／`canceled` 才算結案，可開下一單；含拆單子單）。僅擋 student，系秘／助教直借不受限。
   - **選日期當下就擋（UX，2026-10-02）**：`DatePickerBar` 進頁查一次自己的未歸還單（只查學生），
     點起租日開日曆、或切換租借類型時——同類型有未歸還單 → 提示（附單號，前往查看訂單）不讓選；
     購物車已有同類別訂單 → 一次一張，提示沿用該訂單日期（過期則 Renew）。送單成功後清空日期選擇，
     下一張單必須重新選日期、經過這道檢查。
   其他影響：`DatePickerBar`「Exist Cart 已選日期」多時段清單簡化、
   §5 類型共存表與 §6 重複下單規則需重新對齊（此規則比 §6 嚴格，涵蓋其大部分情境）、
   **遠期預約作廢**（order-lifecycle 情境 4 的 2026-09-26 定案讓位——同類型未歸還即擋，
   無「排隊下一單」）。

## 待確認 / 可能要調整

1. **一個時段只能一間教室** —— 這條**沒有明文寫在任何規則**，是「教室押金 5,000 = 空間押金上限 5,000」湊出來的副作用（第 4 節）。而 5,000 本意是**收費上限**，加第二間押金也不會更多。若要允許一個時段多間教室，只需放寬空間類的「加入時檢查」，結帳的 cap 不動即可。
2. ~~**小量 9 件是否含空間**~~ —— ✅ 定案（2026-09-30）：配合新規則 4 設備／空間分單，
   **9 件額度只計設備，空間不佔額度**（空間自有押金 cap 5,000 天然限量：1 間教室或 5 格一般區塊）。
   實作：`checkLittleBookingLimit` 改為僅計設備（✅ 2026-10-02 隨分單完成）。
3. ~~**訂單流水號跨年不重置**~~ —— 已改為**每年重置**：序號只計當年度（`#${年份}` 開頭）的既有收據數 + 1。（`useOrderSubmission.ts`）
4. **遠期單要擋，細則待與學會討論（2026-09-30）** —— 方向已定：不能下「起租日在很遠未來」的單
   （避免掛一張遠期單把整個類型鎖死，也呼應遠期預約作廢）。待學會定的細則：
   起租日最遠可選幾天內（例如 7／14 天？）、設備大量「今天+3」最小日是否維持、
   空間是否同一套限制。定案後改 `Calendar`／`DatePickerBar` 可選範圍＋`submit_orders` server 端擋。
5. **法定假日在日曆上不可選（Bernard 2026-10-02 提出，待與學會討論）** —— 法定假日（後台自動匯入的
   `closed_dates` kind＝holiday）目前只影響倒數／逾期／歸還期限順延，日曆仍可選為起租日或歸還日。
   方向是同步讓日曆不可選（起租／歸還都不能落在法定假日），待學會確認後再改 `Calendar`。
   **2026-10-03 Bernard 定**：法定假日自動匯入，學會在後台逐日決定是否真的不營業——已實作
   （營業時間頁刪除該日＝照常營業，`autoImportHolidays` 不補回）。
   **日曆不灰化（2026-10-03 Bernard 定，本項結案）**：允許租借期間跨到／落在假日，只有實際歸還要在營業日——
   歸還日落在週末／假日即順延到下個營業日（例：借到週日＝週一還）。灰掉反而讓順延邏輯與日曆選擇打架，
   週末本來就沒灰，學生看得懂。**日曆只灰化寒暑假封鎖**（確定整段不營業，`Calendar` 讀 `fetchBlackouts`）；
   法定假日／公休日都不灰，假日結束後歸還即可。
6. **手動建單（Bernard 評估中，2026-10-02）** —— 要不要提供「學會代學生下單」的服務，或一律由學生自己在系統下單。
